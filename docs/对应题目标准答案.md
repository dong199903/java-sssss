## 01 Java

### 01 List 与数组

**Java 中有哪些集合类？请简单介绍**  
Collection 三大块：`List` 有序可重复（ArrayList / LinkedList）；`Set` 不重复（HashSet / TreeSet / LinkedHashSet）；`Queue` 队列（ArrayDeque / PriorityQueue / 各种 BlockingQueue）。另外 `Map` 不在 Collection 里，是键值对（HashMap / TreeMap / LinkedHashMap / ConcurrentHashMap）。日常默认 ArrayList + HashMap。

**数组和链表在 Java 中的区别是什么？**  
数组（ArrayList 底层）内存连续，按下标 O(1)，CPU 缓存友好，中间插入要搬元素。链表每个节点单独对象，头尾插 O(1)，按下标要走 i 步，是 O(n)。Java 里数组长度固定，List 可扩容。

**List 接口有哪些实现类？**  
常用 `ArrayList`、`LinkedList`、`Vector`（同步、基本淘汰）、`CopyOnWriteArrayList`、`Stack`（继承 Vector，也不推荐）。队列场景优先 `ArrayDeque` 而不是 LinkedList。

**ArrayList 和 LinkedList 有什么区别？**  
ArrayList：`Object[]`，随机访问快，尾部追加均摊 O(1)，中间插入 O(n)。LinkedList：双向链表，头尾快，按下标慢。默认用 ArrayList。

**ArrayList 的扩容机制是什么？**  
空列表容量 0，第一次 add 扩到 10。之后新容量 ≈ 旧容量 × 1.5（`old + (old >> 1)`），`Arrays.copyOf` 拷到新数组。预知数量就指定初始容量。

**栈和队列在 Java 中的区别是什么？**  
栈后进先出（LIFO），队列先进先出（FIFO）。栈用 `ArrayDeque` 的 push/pop，不要用 `Stack`。队列用 `ArrayDeque` / `LinkedList` / 阻塞队列。

### 02 HashMap

**说说 Java 中 HashMap 的原理？**  
JDK 8 是数组 + 链表/红黑树。key 的 hash 扰动后 `(n-1) & hash` 定位桶。冲突拉链；链表长度 ≥ 8 且数组 ≥ 64 树化。负载因子 0.75 扩容 2 倍。key 必须同时重写 hashCode 和 equals。非线程安全。

**Java 中 HashMap 的扩容机制是怎样的？**  
`size > capacity * 0.75` 时容量翻倍。JDK 8 按 hash 的「与 oldCap 对应那一位」把节点分到原下标或 `原下标 + oldCap`，一次遍历完成，不必重新算全部 hash。默认容量 16，大约第 13 个元素触发第一次扩容。

**为什么扩容采用 2 的 n 次方倍？**  
容量为 2 的幂时，`(n-1) & hash` 等价于取模且更快。扩容后只需看多出来的那一位，节点要么不动要么平移 oldCap。

**为什么默认负载因子是 0.75？**  
空间和冲突的折中：更小更少冲突但浪费内存，更大更省空间但链表变长。0.75 是经验值，不是唯一真理。

**为什么 JDK 1.8 引入红黑树？**  
最坏情况哈希碰撞会把链表拉成 O(n)。树化后查找 O(log n)。阈值 8/6 带滞后，避免频繁树化和退化。

**JDK 1.8 对 HashMap 除了红黑树还改了什么？**  
头插改尾插，避免 JDK 7 多线程扩容死链（仍不安全）。hash 扰动简化。扩容改成高低位分裂。`size` 超过阈值才扩。

**HashMap 和 Hashtable 有什么区别？**  
HashMap 允许一个 null key、多个 null value，非同步，JDK 8 有树。Hashtable 全表 synchronized，不允许 null，基本被 CHM 取代。

**HashSet 和 HashMap 有什么区别？**  
HashSet 底层就是 HashMap，元素当 key，value 用同一个 PRESENT 占位。Set 只关心唯一，Map 有键值。

**什么是 Hash 碰撞？怎么解决？**  
不同 key 落到同一桶。HashMap 用拉链 + 树化；也可用开放寻址（ThreadLocalMap）。好的 hashCode 能减少碰撞。

**使用 HashMap 时有哪些提升性能的技巧？**  
预估 size 设初始容量，避免反复 resize。key 的 hashCode/equals 要稳。不要用可变对象当 key。读多写少可考虑不可变拷贝；并发用 CHM。遍历用 entrySet。

### 03 ConcurrentHashMap

**Java 中 ConcurrentHashMap 1.7 和 1.8 之间有哪些区别？**  
1.7 分段锁 Segment，锁粒度粗。1.8 结构对齐 HashMap：空桶 CAS 插入，冲突 synchronized 桶头，size 用 CounterCell（类似 LongAdder）。

**get 方法是否需要加锁？**  
基本不加。数组和 Node 的 val/next 是 volatile，读能看到已发布的写入。

**为什么不支持 key 或 value 为 null？**  
`get` 返回 null 无法区分「没有这个 key」还是「值就是 null」。并发下这个歧义会放大，所以直接禁止。

**ConcurrentHashMap 和 Hashtable 的区别？**  
都线程安全。Hashtable 锁整张表；CHM 锁桶或 CAS，吞吐高得多。CHM 不允许 null。

**Java 线程安全的集合有哪些？**  
CHM、ConcurrentLinkedQueue、CopyOnWriteArrayList、ConcurrentSkipListMap、BlockingQueue 系列。`Collections.synchronizedXxx` 是包装整表锁，性能一般。Vector/Hashtable 属于遗留。

### 04 线程与同步

**Java 中如何创建多线程？**  
实现 Runnable / Callable；继承 Thread（不推荐）；线程池提交任务（推荐）；虚拟线程（21+）。真正跑起来的是 Thread，Runnable 只是任务。

**线程的生命周期在 Java 中是如何定义的？**  
NEW → RUNNABLE（含就绪/运行）→ BLOCKED（等 synchronized）/ WAITING / TIMED_WAITING → TERMINATED。不能从终态回去，也不能两次 start。

**Java 中什么情况会导致死锁？如何避免？**  
互斥、占有并等待、不可抢占、循环等待同时成立。避免：统一加锁顺序、tryLock 超时、缩小锁范围、少嵌套锁。可用 jstack / jcmd 看死锁。

**Synchronized 和 ReentrantLock 有什么区别？**  
见 07。这里先记：synchronized 是 JVM 内置锁，自动释放；ReentrantLock 是 API 锁，可公平、可中断、可 tryLock、必须 finally unlock。

**Java 的 synchronized 是怎么实现的？**  
见 07 锁升级。结合本节：拿不到内置锁的线程进 BLOCKED，不是 WAITING。

### 05 线程池

**你了解 Java 线程池的原理吗？**  
提交顺序：小于 core 就建核心线程 → 否则入队 → 队列满且小于 max 再建线程 → 再满走拒绝策略。`ThreadPoolExecutor` 自己配，别乱用 Executors 的无界队列。

**如何合理地设置 Java 线程池的线程数？**  
CPU 密集约 Ncpu+1；IO 密集可 Ncpu * (1 + 等待/计算)。最终以压测为准，看队列长度、拒绝次数、RT。

**Java 线程池有哪些拒绝策略？**  
AbortPolicy 抛异常（默认）；CallerRunsPolicy 调用者跑（背压）；DiscardPolicy 丢新任务；DiscardOldestPolicy 丢队头再试。

**Java 并发库中提供了哪些线程池实现？它们有什么区别？**  
Fixed：固定线程 + 无界队列。Cached：0 核心、Integer.MAX 最大、同步交接、60s 回收。Single：单线程保证顺序。Scheduled：延时/周期。工作中自己 new ThreadPoolExecutor。

**Java 创建线程池有哪些方式？**  
`new ThreadPoolExecutor(...)`（推荐）；`Executors` 工厂（易踩无界队列/无界线程）；Spring `@Async` + 自定义 TaskExecutor；Java 21 `Executors.newVirtualThreadPerTaskExecutor()`。

**shutdown 与 shutdownNow 的区别？**  
shutdown：不再接新任务，已提交的跑完。shutdownNow：尝试中断在跑的，返回没开始的任务。都要配合 awaitTermination。

**核心线程数运行中能修改吗？**  
能，`setCorePoolSize`。调大可能立即补线程；调小等空闲回收（要允许核心超时则设 `allowCoreThreadTimeOut`）。

**任务出异常后如何知道是哪个线程？**  
默认会进线程的 UncaughtExceptionHandler，Future.get 会把异常包成 ExecutionException。自定义 ThreadFactory 设名字 + 异常处理器；或在任务里自己 catch 打日志。

**DelayQueue 和 ScheduledThreadPool 的区别？什么是 Timer？时间轮？**  
DelayQueue 是延迟阻塞队列，自己还得配消费者。ScheduledThreadPool 是带调度的线程池。Timer 单线程，一个任务卡死全挂，基本不用。时间轮（HashedWheelTimer）适合海量定时，空间换减少比较。

### 06 JMM / volatile / CAS / ThreadLocal

**什么是 Java 内存模型（JMM）？**  
规定工作内存和主内存如何交互，以及 happens-before，用来保证可见性、有序性，并和原子操作一起构成并发正确性基础。不是 JVM 运行时数据区那张图。

**什么是 Java 中的原子性、可见性和有序性？**  
原子：中间状态外不可见（long/double 非 volatile 写在 32 位上不是原子）。可见：一线程写，另一线程能读到。有序：禁止乱序到破坏 happens-before。

**Java 中 volatile 关键字的作用是什么？**  
写后读可见；禁止该变量相关指令重排；读写作内存屏障。不保证复合操作原子（i++ 仍要锁或 Atomic）。

**Java 中的 final 关键字是否能保证变量的可见性？**  
正确构造后，final 字段对其他线程可见（初始化安全）。前提是不要在构造里让 this 逸出。

**什么是 happens-before / 指令重排？**  
编译器、CPU 可重排不相依指令。happens-before 是 JMM 的偏序：unlock→lock、volatile 写→读、线程 start/join、传递性等。有 HB 才保证可见和顺序。

**什么是 Java 的 CAS？什么是 ABA 问题？**  
Compare-And-Swap：原子地「值还是期望值才换成新值」。ABA：A→B→A，CAS 以为没变。用版本号（AtomicStampedReference）缓解。

**使用过哪些原子类 / 累加器？**  
AtomicInteger/Long/Reference；LongAdder/LongAccumulator 高并发累加更合适（分段）。不要拿 Atomic 当通用锁。

**为什么需要 ThreadLocal？如何隔离？key 为何弱引用？最佳实践？缺点？**  
线程内隔离变量。每个 Thread 有 ThreadLocalMap，key 是 ThreadLocal 弱引用，value 强引用。用完 remove，否则线程池会泄露。InheritableThreadLocal 传子线程；TTL 传线程池；Netty FastThreadLocal 更快。

**InheritableThreadLocal / TransmittableThreadLocal / FastThreadLocal？**  
ITL：创建子线程时拷贝。普通线程池复用线程不会重新拷，要用阿里 TTL。FastThreadLocal 用数组下标，少哈希。

**Volatile 与 Synchronized 的区别？synchronized 能不能禁止重排？**  
volatile 轻量，只保证可见和有序，不加锁。synchronized 互斥 + 可见 + 有序（进出锁有屏障，能禁止重排跨越临界区）。需要原子复合操作用 synchronized 或 CAS。

### 07 AQS 与锁

**说说 AQS 吧？**  
AbstractQueuedSynchronizer：用一个 volatile state + CLH 变体队列实现锁/同步器。独占如 ReentrantLock；共享如 Semaphore、CountDownLatch。模板方法：tryAcquire/tryRelease，排队、park/unpark 由 AQS 做。

**Synchronized 和 ReentrantLock 有什么区别？**  
synchronized：JVM 锁，自动释放，非公平为主，锁升级。ReentrantLock：API，必须 unlock，可公平、可中断、可超时、可多条件 Condition。性能现代 JDK 上接近，需要额外能力再用 Lock。

**ReentrantLock 的实现原理？**  
AQS 独占。state 为重入次数。非公平：先 CAS 抢，失败再入队。公平：队列有人就排队。unlock 减 state，到 0 唤醒后继。

**你了解读写锁吗？什么是 StampedLock？**  
ReentrantReadWriteLock：读共享写独占，写锁可降级成读锁，读不能直接升级成写。StampedLock：乐观读 + 印戳，读多写少更高吞吐，不支持重入，用法更易错。

**Java 的 synchronized 是怎么实现的？**  
对象头 Mark Word 存锁状态。偏向锁（已逐步默认关）→ 轻量级锁（CAS）→ 重量级锁（OS mutex）。锁膨胀，主流实现不轻易降级。

**轻量级锁是否会自旋？自适应自旋？升级到重量级后还会降吗？**  
会自旋一阵再膨胀。自适应根据上次成功与否调自旋次数。升到重量级后，HotSpot 通常不降回轻量。

**如何优化锁的使用？**  
缩小范围、降低粒度（分段、CHM）、读写分离、能无锁用 CAS、避免在锁里 IO、减少持锁时间。先测再优化。

### 08 JVM 与 GC

**JVM 由哪些部分组成？**  
类加载子系统、运行时数据区、执行引擎（解释器 + JIT）、本地方法接口、GC。

**JVM 的内存区域是如何划分的？**  
线程私有：程序计数器、虚拟机栈、本地方法栈。线程共享：堆、方法区（元空间）。直接内存不在堆，NIO 会用。

**编译执行与解释执行的区别？JVM 用哪种？**  
解释逐条执行，启动快。编译成本地代码，跑得快。HotSpot 混合：先解释，热点 JIT（C1/C2），分层编译。

**Java 中有哪些垃圾回收算法？**  
标记-清除、标记-整理、复制。分代：年轻代复制，老年代标记整理/区域化（G1）。引用计数 Java 不用（循环引用）。

**常见垃圾收集器有哪些？**  
Serial / Parallel / CMS（已删）/ G1（JDK 9+ 默认）/ ZGC / Shenandoah。现在面试重点 G1 和 ZGC。

**为什么 Java 8 用元空间替换永久代？**  
永久代在堆上，易 OOM、调参痛苦。元空间用本地内存存类元数据，默认跟机器内存走，减少 PermGen OOM。

**GC 调优目标 / 如何调优 / 常用 JVM 参数**  
目标：停顿可控、吞吐够、不 OOM。先看 GC 日志和业务 RT，再改。常用：`-Xms -Xmx`、`-XX:+UseG1GC`、`-Xlog:gc*`、`-XX:MaxGCPauseMillis`。不要一上来乱调。

**哪几种情况会 OOM？OOM 后怎么分析？**  
堆（对象泄漏/峰值）、元空间（动态类太多）、直接内存、栈（极少 OutOfMemoryError，更多 StackOverflowError）、GC overhead。分析：留 heap dump（`-XX:+HeapDumpOnOutOfMemoryError`），MAT 看 dominator；栈用 jstack。

**怎么分析当前内存占用？**  
`jcmd <pid> VM.native_memory`、`jmap -histo`、`jstat -gcutil`、VisualVM/Arthas。看堆、元空间、直接内存分开看。

### 09 equals、OOP、传值

**Java 中 hashCode 和 equals 方法是什么？它们与 == 有什么区别？**  
`==` 比引用（基本类型比值）。`equals` 默认也是 ==，可重写成业务相等。`hashCode` 是哈希码，给哈希表用。

**hashCode 和 equals 之间有什么关系？**  
equals 为 true，hashCode 必须相等。hashCode 相等，equals 不一定 true。放进 HashMap/HashSet 的 key **必须两个一起改**。

**Java 中的参数传递是按值还是按引用？**  
按值。传的是副本：基本类型拷贝值，对象拷贝引用。方法里改引用指向不影响外面，改对象内部字段会影响。

**什么是 Java 的多态特性？**  
编译看父类型，运行调子类重写方法（动态绑定）。前提：继承/实现 + 重写 + 父类引用指向子类。

**接口和抽象类有什么区别？**  
抽象类可以有成员变量、构造、已实现方法；单继承。接口多实现，字段默认 public static final；Java 8+ 可有 default/static 方法。是什么用接口，是一类东西用抽象类。

**为什么 Java 不支持多重继承？**  
避免菱形问题（两个父类同一方法不知听谁）。用接口多实现替代。

**方法重载和方法重写的区别？**  
重载：同类同名不同参，编译期决定。重写：子类同签名改实现，运行期绑定。返回类型协变可以。

**什么是继承 / 封装？访问修饰符有哪些？**  
封装：藏实现，暴露接口。继承：复用 IS-A。修饰符：private / 默认包内 / protected / public。

**静态方法和实例方法的区别？**  
静态属类，无 this，不能直接用实例成员，不多态。实例属对象，可重写。

**Object 类中有什么方法？**  
equals、hashCode、toString、getClass、clone、wait/notify/notifyAll、finalize（已弃）。

**PO、VO、BO、DTO、DAO、POJO 有什么区别？**  
PO 库表映射；DTO 跨层传输；VO 展示；BO 业务对象；DAO 数据访问；POJO 普通 Java 对象。别把一层对象传到所有层。

### 10 String、装箱

**String、StringBuffer、StringBuilder 的区别？**  
String 不可变。StringBuilder 可变、非同步、拼串用它。StringBuffer 同步、基本被 Builder 取代。

**StringBuilder 是怎么实现的？**  
内部 byte[]/char[]，append 不够就扩容（大约 2 倍），`toString` 再拷成 String。

**为什么 JDK 9 把 String 的 char[] 改成 byte[]？**  
Latin-1 用 1 字节，省内存。coder 标记 LATIN1/UTF16。

**使用 new String("yupi") 会创建多少个对象？**  
字面量 "yupi" 进常量池（若没有则创建一个）；new 在堆再创建一个 String 对象指向它。所以最多 2 个（池里已有则 1 个堆对象）。

**包装类型和基本类型的区别？**  
包装是对象，可 null，有方法；基本类型在栈上更轻。集合只能装包装。拆箱 null 会 NPE。

**什么是自动装箱拆箱？**  
`Integer x = 1` 调 valueOf；`int y = x` 调 intValue。循环里装箱会有性能和 NPE 坑。

**什么是 Integer 缓存池？**  
`valueOf` 默认缓存 -128~127。范围内同一对象，范围外每次 new。比较数值用 equals，不要 ==。

**什么是不可变类？**  
创建后状态不可改：final 类、final 字段、没有 setter、可变成员做防御拷贝。String、包装类型、LocalDate 都是。

**BigDecimal 是什么？为什么能保证精度？**  
用整数 unscaled value + scale 表示十进制，避开二进制浮点误差。金额用它。比较用 compareTo，不要 new BigDecimal(double)，用字符串或 valueOf。

**Float 运算后如何判断相等？**  
不要 ==。用误差范围，或转 BigDecimal。金额不要用 float/double。

**Java 中的基本数据类型有哪些？**  
byte/short/int/long、float/double、char、boolean。对应包装 Byte…Boolean。

**为什么会遇到乱码？**  
编码和解码不是同一套（文件、HTTP、数据库、JVM）。统一 UTF-8，别混 GBK。

### 11 异常与 wait/sleep

**Exception 和 Error 有什么区别？**  
都是 Throwable。Exception 可恢复（检查型/运行时）；Error 是 JVM 层面（OOM、StackOverflow），一般不捕获。

**运行时异常和编译时异常的区别？**  
RuntimeException 及子类不用声明，编程错误居多。检查型必须 catch 或 throws。

**final、finally、finalize 各是什么？**  
final：不可改/不可继承/不可重写。finally：try 后必走（除非 VM 挂、或 finally 前杀进程）。finalize：GC 前钩子，已弃用。

**wait() 和 sleep() 的区别？**  
wait 是 Object 方法，必须在 synchronized 里，释放锁并进入 WAITING。sleep 是 Thread 方法，不释放锁，TIMED_WAITING。醒来 wait 要重新抢锁。

**Thread.sleep 和 yield 的区别？**  
sleep 指定时间不参与调度。yield 提示让出 CPU，仍是 RUNNABLE，不保证真让。

**一个线程被两次 start 会发生什么？**  
第一次合法。第二次抛 IllegalThreadStateException，终态不能重生。要再跑就 new 一个 Thread。

### 12 泛型、拷贝、序列化

**Java 泛型的作用是什么？**  
编译期类型检查，少强转。本质是语法糖。

**泛型的上下界限定符？**  
`? extends T` 生产者（能取不能乱放）；`? super T` 消费者（能放 T，取出是 Object）。PECS。

**泛型擦除是什么？**  
运行时 List\<String\> 和 List\<Integer\> 都是 List。边界擦成上界（默认 Object）。所以不能 `new T()`、不能用原始类型数组稳妥地泛型化。

**深拷贝和浅拷贝有什么区别？**  
浅拷贝复制引用；深拷贝递归复制内部对象。clone 默认浅拷贝。可变对象做防御拷贝。

**序列化和反序列化是什么？**  
对象 ↔ 字节流。Java 原生 Serializable + serialVersionUID。跨语言用 JSON/Protobuf。反序列化有安全风险，别反序列化不可信数据。

### 13 反射、注解、SPI、代理

**你使用过反射吗？如何应用？**  
运行时拿 Class/构造/方法/字段。框架扫描、JSON、Spring IOC 都靠它。慢、破坏封装，业务代码少用。

**注解原理是什么？**  
源码标记，保留策略 SOURCE/CLASS/RUNTIME。RUNTIME 的可用反射读。本质是实现了注解接口的代理对象。

**什么是 SPI？**  
Service Provider Interface：接口在核心，实现由 classpath 下 `META-INF/services/` 提供。JDBC Driver、Spring Boot 自动配置早期机制。Java 用 ServiceLoader。

**什么是动态代理？**  
运行时生成代理类，把调用转给 InvocationHandler。AOP、RPC 常用。

**JDK 动态代理和 CGLIB 的区别？**  
JDK：必须接口，java.lang.reflect.Proxy。CGLIB：继承目标类，final 方法拦不了。Spring AOP 有接口走 JDK，否则 CGLIB。

**内部类是什么？有什么作用？**  
成员内部类、静态内部类、局部、匿名。能访问外部类私有成员。静态内部类不持有外部 this，更干净。lambda 大量替代匿名类。

### 14 类加载

**Java 的类加载过程是怎样的？**  
加载 → 验证 → 准备（静态字段默认值）→ 解析（符号变直接引用，可延迟）→ 初始化（\<clinit\>）。使用时触发初始化。

**什么是双亲委派模型？**  
先委派父加载器，找不到自己加载。保证 java.lang.Object 等唯一。SPI、热部署会破坏委派（线程上下文加载器）。

**字节码是什么？**  
.class 里的指令，JVM 的中间表示。javap 可看。不是机器码，JIT 才变机器码。

**JDK 和 JRE 有什么区别？**  
JRE：运行。JDK：JRE + javac 等开发工具。现在发行版一般直接给 JDK。

**你使用过哪些 JDK 工具？**  
javac/java/jar、jps、jstack、jmap、jstat、jcmd、javap、jhsdb、MAT、Arthas。

**Java 的优势是什么？面向对象和面向过程的区别？**  
一次编写到处运行、生态、内存管理、并发库。面向对象：数据+行为封装，多态复用。面向过程：函数流程。

**Java8 / 11 / 17 / 21 / 25 有哪些新特性？**

**Optional 类是什么？**  
可能为空的容器，逼你处理空。别在字段上用，别 `get()` 乱调用。适合返回值。

**什么是协程？Java 支持吗？**

**foreach 和 for 的区别？什么是 Iterator？**  
增强 for 编译成 Iterator。Iterator 可 fail-fast。普通 for 按下标，适合 ArrayList 随机访问。

### 16 COW、fail-fast、其他 Map

**你遇到过 ConcurrentModificationException 吗？如何产生？**

### 17 同步工具

**你使用过哪些并发工具类？Semaphore / CyclicBarrier / CountDownLatch？**  
CountDownLatch：一次性门闩，主线程等 N 个任务。CyclicBarrier：N 个线程互相等，可循环。Semaphore：许可证，限流。

**什么是 CompletableFuture / ForkJoinPool？**

**Synchronized 修饰静态方法和实例方法的区别？**

见 06。

**synchronized 能不能禁止指令重排？**

## 02 MySQL

### 01 一条 SQL 的执行过程

**详细描述一条 SQL 语句在 MySQL 中的执行过程。**  
连接器（认证、权限）→ 查询缓存（8.0 已删）→ 解析器（语法树）→ 分析器/预处理器 → 优化器（选索引、JOIN 顺序）→ 执行器调存储引擎。InnoDB 走 Buffer Pool，必要时读磁盘；改数据先写 undo/redo，提交再涉及 binlog。返回结果。

### 02 存储引擎

**MySQL 的存储引擎有哪些？它们之间有什么区别？**  
InnoDB（默认）：事务、行锁、MVCC、聚簇索引、崩溃恢复。MyISAM：表锁、不支持事务，已少用。Memory：内存表。业务表用 InnoDB。

### 03 B+ 树与索引

**为什么 MySQL 选择 B+ 树？**  
矮胖、扇出大、层数少；叶子链表顺序扫；非叶只存键，更多键进一页。哈希不能范围查；B 树非叶也带数据，扇出更小。

**请详细描述 B+ 树中查询数据的全过程**  
从根到叶逐层二分。主键聚簇索引叶子就是整行。二级索引叶子是主键值，再拿主键回表。

**三层 B+ 树能存多少数据？**  
页 16KB。非叶约几百到一千多指针，三层轻松千万到上亿行量级（视键长）。所以 InnoDB 高度通常 3～4 层。

**聚簇索引和非聚簇索引的区别**  
聚簇：叶子是数据行，InnoDB 主键。非聚簇/二级：叶子是主键（InnoDB）或行指针（MyISAM）。

**回表是什么？**  
二级索引找到主键，再回主键索引取整行。覆盖索引可避免回表。

**索引类型有哪些？**  
主键、唯一、普通、联合、前缀、全文、空间。按结构主要是 B+；还有哈希（自适应，引擎内部）。

### 04 索引使用

**最左前缀匹配原则**  
联合索引 (a,b,c) 从左用。`a`、`a,b`、`a,b,c` 能用；只 `b` 或 `a,c` 里 c 可能用不上。范围条件会截断后面。

**覆盖索引 / 索引下推**  
覆盖：SELECT 列都在索引里，不回表。ICP：引擎层先按索引条件过滤再回表，减少回表次数。

**建索引要注意什么**  
区分度高的列在前；不要过长字符串；联合索引覆盖常用 WHERE+ORDER；避免过多索引拖慢写。

**使用索引一定有效吗？如何排查**  
不一定。优化器可能因选择性差、函数破坏、类型隐式转换而放弃。用 EXPLAIN 看 type/key/rows/Extra。

**索引是不是越多越好**  
不是。每个索引占空间、拖累 INSERT/UPDATE。只建用得上的。

**count(*) / count(1) / count(列)**  
InnoDB 下 `*` 和 `1` 差不多，都要扫。`count(列)` 不统计 NULL。没有 MyISAM 那种表行数缓存。

### 05 隔离级别

**脏读、不可重复读、幻读**  
脏读：读到未提交。不可重复读：同一行两次读值变了（被改）。幻读：范围行数变了（被插删）。

**事务隔离级别有哪些**  
读未提交、读已提交（RC）、可重复读（RR）、串行化。级别越高并发越低。

**默认隔离级别是什么，为什么**  
InnoDB 默认 RR。用 MVCC + 间隙锁尽量避免幻读，适合很多业务「一个事务里两次读一致」。不少互联网公司改成 RC 减少间隙锁。

**MySQL 如何实现事务**  
undo 回滚 + MVCC；redo 崩溃恢复；提交两阶段对齐 binlog。锁保护写冲突。

**事务的二阶段提交是什么**  
redo prepare → 写 binlog → redo commit。崩溃后按 binlog 有无决定提交还是回滚，保证引擎和 binlog 一致。

### 06 MVCC

**MySQL 中的 MVCC 是什么？**  
多版本：每行有 trx_id、roll_pointer。读视图（Read View）决定能见哪些版本，旧版本从 undo 链取。RC 每次语句新视图，RR 事务开始建一次。

**长事务可能导致哪些问题？**  
undo 不能清、MVCC 链变长、锁持有久、备份和 DDL 受阻、主从延迟。尽快提交，别在事务里等用户。

### 07 锁

**MySQL 中有哪些锁类型？**  
粒度：表锁、意向锁、行锁。行：记录锁、间隙锁、next-key（RR 默认）。还有插入意向锁、自增锁。算法：乐观（版本号）vs 悲观（真加锁）。

**乐观锁和悲观锁**  
乐观：读时不加锁，更新带版本号 `WHERE version=?`。悲观：一上来 `SELECT FOR UPDATE`。冲突少用乐观，冲突多用悲观。

**发生死锁如何解决？**  
InnoDB 会检测并回滚代价小的事务。应用：固定加锁顺序、减小事务、RC 少间隙锁、拿 innodb status / 死锁日志分析。

### 08 优化与架构

**如何使用 EXPLAIN**  
看 id、select_type、type（const/ref/range/index/ALL）、possible_keys、key、rows、filtered、Extra（Using index / Using filesort / Using temporary）。

**如何 SQL 调优**  
EXPLAIN + 慢日志。能走索引就别函数包列；避免 SELECT *；控制 JOIN；深度分页改游标；必要时刻分库分表。

**如何解决深度分页**  
`LIMIT 100000,10` 要扔掉 10 万行。改成 `WHERE id > last_id ORDER BY id LIMIT 10`，或延迟关联（先索引查 id 再回表）。

**select * 一千万行内存会飙吗**  
会。结果集进网卡和客户端内存。要聚合、分页、只选需要的列。

**主从同步机制 / 如何处理延迟**  
主写 binlog，从 IO 线程拉、SQL 线程放。延迟：大事务、从库差、并行复制没开好。处理：查从库延迟、拆事务、并行复制、关键读走主。

**什么是分库分表，有哪些策略**  
数据量/QPS 超出单机。垂直拆业务；水平按 shard key（用户 id 取模、范围、一致性哈希）。要解决跨库 JOIN、分布式事务、扩容迁移。

### 09 redo / undo / binlog

**binlog、redo log、undo log 的作用和区别？**  
redo：物理/逻辑混合，崩溃重做已提交改动，循环写。undo：回滚 + MVCC 旧版本。binlog：Server 层逻辑日志，复制和备份。

**什么是 WAL？MySQL 用到了吗？**  
Write Ahead Log：先日志后数据页。InnoDB redo 就是 WAL。

**事务的二阶段提交是什么？**  
见 05。

**插入一条 SQL，redo 记录的是什么？**  
页级改动（物理日志），用来把 Buffer Pool 里脏页在崩溃后重放出来。不是整条 SQL 文本（那是 binlog statement/row）。

**从磁盘读还是 Buffer Pool？Change Buffer / Doublewrite / Log Buffer？**  
先 Buffer Pool。Change Buffer：二级索引页不在内存时先缓存变更。Doublewrite：防页写一半。Log Buffer：redo 的内存缓冲。

**MySQL 如何实现事务？**  
见 05。

### 10 类型与 SQL 杂项

**varchar 和 char 的区别？VARCHAR(100) 和 VARCHAR(10)？**  
char 定长，varchar 变长。InnoDB 下 100 和 10 的「上限」影响最大行长和索引前缀，不是磁盘一定占 100。按真实长度选，别盲目 255。

**DATETIME 和 TIMESTAMP？**  
DATETIME 范围大、与时区无关（存字面）。TIMESTAMP 转 UTC，范围到 2038，自动更新方便。业务时间常用 DATETIME。

**count(*)、count(1)、count(字段) 的区别？**  
见 04。

**int(11) 的 11 表示什么？**  
显示宽度，不影响存储范围。int 永远 4 字节。

**存储金额用什么类型？**  
`DECIMAL`，不要 float/double。

**TEXT 最大多长？AUTO_INCREMENT 到上限？**  
TEXT 64KB，MEDIUMTEXT 16MB，LONGTEXT 4GB。自增到类型上限再插报错，用 BIGINT。

**一张表最多多少列？不推荐存图片音视频？**  
行格式限制，大约一千列量级，实际远不该这么宽。大文件放对象存储，表里存 URL。

**三大范式？视图、游标、存储过程？**  
1NF 原子；2NF 非主键依赖主键；3NF 无传递依赖。视图是虚拟表；游标逐行（少用）；存储过程库内逻辑（不好扩、难版本管理，业务慎用）。

**DELETE / DROP / TRUNCATE？逻辑删除？逻辑外键？**  
DELETE 行级可回滚、可条件。TRUNCATE 快、DDL、自增重置。DROP 删表。逻辑删除加 deleted 标记。逻辑外键应用层维护，InnoDB 物理外键影响迁移和性能，大厂常用逻辑。

**select/from/join/where 的执行顺序？**  
逻辑上 FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT。和书写顺序不同。

### 11 JOIN 与分页

**INNER / LEFT / RIGHT JOIN 的区别？**  
INNER 两边都有。LEFT 左全保留，右无则 NULL。RIGHT 相反。业务多用 INNER/LEFT。

**为什么不推荐多表 JOIN？**  
优化器难、难走对索引、中间结果大。可拆查询、冗余、或数据组内 JOIN。

**LIMIT 大偏移和 LIMIT 10 速度一样吗？深度分页？游标分页？**  
不一样。深度分页见 08。游标分页用上一页最后 id。

**EXISTS 和 IN？查询优化器如何选计划？**  
现代优化器常等价改写。相关子查询看 EXPLAIN。优化器基于统计信息选代价最低计划，统计过期会选错，需 ANALYZE。

**建表要注意什么？何时不该建索引？**  
InnoDB、主键、字符集 utf8mb4、金额 DECIMAL、时间 DATETIME、必备索引。低区分度、极少过滤、极频繁写的列别乱建。

**全量同步和增量同步？CDC？批量入库？**  
全量一次拷。增量 binlog/CDC 持续追。批量用 LOAD 或 batch insert，控制事务大小。

**不停服迁移？读写分离？主从延迟？分库分表？**  
双写或 CDC 切流；读从写主要注意延迟；分库分表见 08。

## 03 Redis

### 01 为什么快

**Redis 通常应用于哪些场景？**  
缓存、分布式锁、会话、排行榜、计数、限流、消息（轻量）、GEO、布隆、UV 统计。

**Redis 为什么这么快？**  
内存、单线程执行命令无锁、IO 多路复用、简单数据结构、协议轻。不是「单线程所以快」，是少切换少锁。

**为什么设计成单线程？6.0 为何引入多线程？**  
命令执行单线程避免并发改同一结构。6.0 多线程在读 socket / 写回包，执行仍单线程。

**Redis 和 Memcached 有哪些区别？**  
Redis 数据结构丰富、持久化、复制集群。Memcached 纯内存 KV、多线程、不持久。现在缓存 Redis 为主。

**项目里用的 Redis 客户端是什么？**  
Lettuce（Netty、可共享连接，Spring Boot 默认）；Jedis 要池。Redisson 高级锁/集合。

### 02 数据类型

**Redis 中常见的数据类型有哪些？**  
String、Hash、List、Set、ZSet，以及 Bitmap、HyperLogLog、GEO、Stream。

**Redis 的 hash 是什么？**  
field-value 的 map。对象、购物车常用。小 hash 用 listpack/ziplist，大了转 hashtable。

**跳表的实现原理**  
多层有序链表，高层是「快进」。期望 O(log n) 查找。ZSet 字典 + 跳表。

**如何用 Redis 实现排行榜**  
ZSet：score 分数，member 用户。`ZINCRBY`、`ZREVRANGE`。同分再拼时间戳。

**如何实现布隆过滤器（判一定不存在，有假阳）**  
多哈希映射到位图。说「没有」一定没有；说「有」可能误判。RedisBloom 模块或自己 Bitmap。不能删（Counting Bloom 除外）。

### 03 过期与淘汰

**数据过期后的删除策略**  
惰性：访问时发现过期删除。定期：随机抽一批删。不是到点立刻全删。

**有哪些内存淘汰策略**  
noeviction 满了报错；volatile-lru/lfu/ttl/random 只对设了 TTL 的；allkeys-lru/lfu/random 对所有 key。缓存常用 allkeys-lru。

**Redis 内存溢出怎么排查**  
`INFO memory`、`MEMORY USAGE`、`redis-cli --bigkeys`、看 maxmemory 和淘汰策略、是否大 key/没 TTL。

**线上 Redis 机器爆了如何优化**  
拆大 key、加 TTL、换淘汰策略、压缩 value、拆实例/集群、别当数据库用。

### 04 持久化与高可用

**持久化机制有哪些**  
RDB 快照；AOF 写命令。4.0+ RDB-AOF 混。看业务能丢几秒选 fsync 策略。

**生成 RDB 时如何处理请求**  
fork 子进程，写时复制。父进程继续服务。瞬时内存可能涨。

**主从复制原理 / 常见拓扑 / 复制延迟原因**  
全量 RDB + 增量 backlog。一主多从、树形。延迟：弱网、大 key、从库阻塞、单线程执行。

**哨兵机制**  
监控、自动故障转移、通知客户端新主。本身要 3 节点防脑裂。

**集群实现原理 / 如何根据键定位节点**  
16384 slot，`CRC16(key) % 16384`。MOVED/ASK 重定向。hash tag `{userId}` 把相关 key 放同槽。

**Cluster 与 Sentinel 的区别**  
Sentinel：主从 + 哨兵，容量单机内存上限。Cluster：分片 + 自举故障转移，水平扩展。

**集群会脑裂吗**  
少数派主节点网络分区可能短暂双主。min-replicas、多数派、客户端重试幂等。不能 100% 当 CP。

### 05 缓存问题

**缓存击穿、穿透、雪崩是什么**  
穿透：查不存在的，打到 DB。布隆 + 空值短 TTL。击穿：热点过期，一堆请求打 DB。互斥锁重建或逻辑过期。雪崩：大量同时过期或 Redis 挂。TTL 加随机、高可用、降级。

**如何保证缓存与数据库一致性**  
没有完美强一致。常用 Cache Aside：先更 DB 再删缓存；失败重试/补偿。延迟双删减并发窗口。要强一致考虑不缓存或用事务消息。

**如何实现布隆过滤器（结合穿透）**  
见 02。布隆挡「一定没有」的穿透。

### 06 分布式锁

**Redis 中如何实现分布式锁**  
`SET key uniqueId NX PX ttl`，释放用 Lua 校验 value 再 DEL。不能只 SETNX 忘过期，不能 DEL 掉别人的锁。

**实现时可能遇到的问题**  
过期了业务还在跑 → 看门狗续期（Redisson）。主从切换丢锁 → 不能只靠异步复制，Redlock 有争议。可重入、锁粒度、锁错资源。

**Redisson 分布式锁原理**  
hash + 过期，看门狗约 1/3 TTL 续期。可重入。 Palantir/Redlock 多节点。unlock 用 Lua。

**分布式锁一般都怎样实现（场景题）**  
Redis 性能好；ZK/etcd 靠会话更稳。按能不能容忍锁丢失选。

### 07 运维向

**Big Key 问题如何解决**  
拆、压缩、SCAN 不要 KEYS、序列化改 protobuf、hash 分片。删除用 UNLINK。

**如何解决热点 key**  
本地缓存、随机到多副本 key、读写分离、业务打散。

**Redis 支持事务吗**  
MULTI/EXEC 排队执行，**不回滚**，中间失败后面继续。要原子用 Lua。

**Lua 脚本是什么、怎么用**  
服务器内原子执行。EVAL。保证逻辑在同一 slot（集群）。

**Pipeline 是什么**  
一批命令一次往返，减少 RTT。不原子，中间别人可能插队。原子用 Lua 或 MULTI。

**Redis 性能瓶颈如何处理**  
大 key、热 key、慢命令（KEYS、大集合）、网络、fork RDB。慢日志 + INFO + 监控。

### 08 SDS 与编码

**String 底层 SDS？EMBSTR 阈值为什么是 44？**  
SDS：len、alloc、buf，O(1) 长度、二进制安全。embstr 一次分配对象+数据；超过约 44 字节（jemalloc 分箱）改 raw。

**Ziplist / Quicklist / ListPack？**  
紧凑连续编码，省内存。list 用 quicklist（ziplist 串起来）；新版本 listpack 替代 ziplist。元素多或太大就转hashtable/skiplist。

**List 常见命令？如何实现队列和栈？**  
LPUSH/RPUSH/LPOP/RPOP。队列一端进一端出；栈同一端进出。

**Zset 原理？为什么用跳表不是红黑树/B+？**  
dict + skiplist。跳表实现简单、范围查询友好、内存局部性尚可。B+ 更适合磁盘页。

**Pipeline 和 MSET/MGET 的区别？**  
MSET/MGET 是一条命令。Pipeline 是多条命令打包。MSET 原子，Pipeline 不原子。

**事务和关系库事务的区别？Lua？**  
无隔离无回滚。Lua 是真原子脚本。

**内存碎片化？虚拟内存 VM？**  
jemalloc 仍可能碎片，`MEMORY PURGE` / 重启。旧版 VM 把冷数据换盘，已废弃，别当虚拟内存数据库用。

### 09 布隆 / UV / GEO

**如何用 Redis 实现布隆过滤器？**  
见 02。RedisBloom 或 Bitmap 自己哈希。

**如何统计大量用户 UV？**  
HyperLogLog：`PFADD`/`PFCOUNT`，误差约 0.81%，固定 12KB 级。要精确用 Set，占内存。

**GEO 是什么？**  
地理坐标，底层 ZSet + GeoHash。附近的人、距离。

**订阅发布了解吗？**  
PUB/SUB，不持久、不保证到达。可靠消息用 Stream。

**Redis 通常应用于哪些场景？**  
见 01。

**和 Memcached 的区别？客户端是什么？字符串最大值？**  
见 01。String 最大 512MB。

## 04 Spring

### 01 IoC / DI

**什么是 Spring IOC？IOC 有什么好处？**  
控制反转：对象创建和依赖交给容器，不要满地 new。好处：解耦、可测、统一生命周期。

**Spring 中的 DI 是什么？有几种注入方式？**  
依赖注入是 IOC 的实现。构造器（推荐）、setter、字段 `@Autowired`。构造器利于不可变和必依赖。

**Spring 由哪些重要模块组成？**  
Core（IoC）、AOP、Data Access、Web/MVC、Test、Boot/Cloud 在其上。BeanFactory 是底层容器，ApplicationContext 更完整。

**什么是 Spring Bean？ApplicationContext 是什么？**  
Bean 是容器管理的对象。ApplicationContext 是 IoC 容器：读配置、创建 Bean、发事件、国际化和 AOP。

### 02 Bean 生命周期与启动

**说下 Spring Bean 的生命周期？**  
实例化 → 属性填充 → Aware → BeanPostProcessor 前置 → InitializingBean/`@PostConstruct`/init-method → BPP 后置（AOP 代理常在这）→ 使用 → `@PreDestroy`/DisposableBean/destroy-method。

**说说 Spring 启动过程？**  
创建 ApplicationContext → 读 BeanDefinition → BeanFactoryPostProcessor（含 ConfigurationClassPostProcessor）→ 注册 BPP → 预实例化单例 → 发布完成事件。

**说说 Spring Boot 的启动流程？**  
`SpringApplication.run`：推断 Web 类型、加载 ApplicationContext、准备 Environment、打印 Banner、创建上下文、加载 starter 自动配置、refresh、调用 Runner。

**Spring Boot 如何通过 main 启动 Web 项目？**  
main 里 run 后 refresh 会启动内嵌 Tomcat/Jetty（ServletWebServerApplicationContext），阻塞在容器上，不是 main 立刻结束。

### 03 循环依赖

**什么是循环依赖？**  
A 依赖 B、B 依赖 A。构造器环容器创建失败；字段/setter + 单例可以靠提前暴露解决。

**Spring 如何解决循环依赖？**  
单例字段注入：实例化后把工厂放进三级缓存，对方注入时拿到早期引用，再继续初始化。prototype 不支持。构造器环要用 `@Lazy` 或拆类。

**为什么需要三级缓存，二级不够吗？**  
有 AOP 时不能一实例化就当成品。三级是工厂，真正注入时才 `getEarlyBeanReference` 生成代理，避免「注入原对象、容器里是代理」。

### 04 AOP

**什么是 AOP？AOP 术语 / 通知类型？**  
横切：日志、事务、权限。切面 Aspect、切点 Pointcut、连接点 JoinPoint、通知 Advice：Before/After/AfterReturning/AfterThrowing/Around。

**Spring AOP 默认用什么动态代理，两者区别？**  
有接口 JDK 代理，否则 CGLIB。JDK 基于接口；CGLIB 继承类，final 拦不住。

**Spring AOP 和 AspectJ 有什么区别？**  
Spring AOP 运行时代理，只能拦 Spring Bean 的 public 方法调用。AspectJ 可编译期织入，能拦更多（字段、构造）。日常事务用 Spring AOP 够。

**能说说拦截链的实现吗？**  
多个 Advisor 排成链，MethodInterceptor 套娃，Around 最外。`ReflectiveMethodInvocation.proceed()` 往下走。

**Spring 都用到哪些设计模式？**  
工厂（BeanFactory）、单例、代理（AOP）、模板（JdbcTemplate）、观察者（事件）、策略（Resource）、适配器（AdvisorAdapter）。

### 05 事务

**Spring 有哪几种事务传播行为？有什么用？**  
常用 REQUIRED（加入或新建）、REQUIRES_NEW（挂起旧的、新开）、NESTED（嵌套保存点）、SUPPORTS、NOT_SUPPORTED、MANDATORY、NEVER。控制「要不要新事务」。

**Spring 事务有几个隔离级别？**  
DEFAULT 跟数据库；其余对应 RU/RC/RR/SERIALIZABLE。

**事务在什么情况下会失效？**  
非 public；自调用没走代理；异常被吃掉；抛的是检查型且没 rollbackFor；传播/数据源不对；没被 Spring 管理。

### 06 MVC

**Spring MVC 具体的工作原理？核心组件？**  
DispatcherServlet 收请求 → HandlerMapping 找处理器 → HandlerAdapter 调 Controller → 返回 ModelAndView → ViewResolver 渲染。异常 HandlerExceptionResolver。

**说下对 Spring MVC 的理解？父子容器？**  
Web 层子容器（Controller），根容器（Service/Dao）。子能看见父，父看不见子。Boot 默认常常合成一个。

**Spring 和 Spring MVC 的关系？**  
MVC 是 Spring 的 Web 模块，IoC 容器上的一套 Servlet 框架。Boot 把内嵌容器和自动配置加上。

**拦截器和过滤器有什么区别？**  
见 11。

### 07 Boot

**什么是 Spring Boot？**  
约定优于配置，快速建 Spring 应用：starter、自动配置、内嵌服务器、Actuator。

**核心特性有哪些？**  
自动配置、starter、独立运行、生产监控、无 XML。

**如何理解 starter？**  
依赖聚合 + 自动配置类。引入 `spring-boot-starter-web` 就有 MVC 和 Tomcat。

**如何实现自动配置？**  
`spring.factories` / `AutoConfiguration.imports` 列出 `*AutoConfiguration`，`@ConditionalOn*` 满足才生效。可被 `application.yml` 覆盖。

**main 方法如何启动 Web 项目？**  
见 02。

**Spring Boot 启动流程**  
见 02。

### 08 Cloud

**分布式和微服务的区别**  
分布式：拆到多机。微服务：按业务拆独立部署的服务，是分布式的一种架构风格。

**配置中心 / API 网关**  
配置中心：集中配置、动态刷新（Nacos/Apollo）。网关：入口鉴权、路由、限流（Gateway）。

**Dubbo 和 Spring Cloud Gateway 的区别**  
Dubbo 是 RPC 框架；Gateway 是 HTTP 网关。不是一类东西。Cloud 常用 OpenFeign+Gateway，也可以 Dubbo。

**HTTP 与 RPC**  
HTTP 通用、有路径/状态码。RPC 强调接口、序列化、服务发现，吞吐和治理更强（gRPC/Dubbo）。

**负载均衡算法**  
轮询、随机、加权、最少连接、一致性哈希。客户端（Ribbon/LoadBalancer）或网关/Nginx。

**服务雪崩 / 熔断 / 降级**  
下游挂导致线程耗尽传导。熔断：失败率高就开路。降级：返回兜底。限流保护自己。Resilience4j/Sentinel。

**什么情况需要分布式事务，有哪些方案**  
跨库/跨服务要原子。方案：尽量避免（本地消息表、最终一致）；要强一致用 Seata AT/TCC、Saga。2PC 重、慢。

**什么是 Seata**  
阿里分布式事务：TM/RM/TC。AT 改 SQL 加 undo；TCC 手动 try/confirm/cancel。

### 09 FactoryBean 与注解

**BeanFactory / FactoryBean / ObjectFactory / ApplicationContext？**  
BeanFactory：容器。FactoryBean：自己是工厂，`getObject()` 才是产品（如 SqlSessionFactoryBean）。ObjectFactory：延迟拿 Bean。ApplicationContext 扩展 BeanFactory。

**Bean 有几种作用域？**  
singleton、prototype、request、session、application。Web 才有后三个。

**有几种注入方式？自动装配方式？Bean 注册方式？**  
注入见 01。装配：byType/byName/`@Autowired`。注册：xml、`@Component` 扫描、`@Bean`、Import、FactoryBean。

**@Bean 和 @Component 区别？@Component/@Controller/@Service/@Repository？**  
@Component 及衍生：类上扫描。@Bean：方法产出，适合第三方类。四层注解语义分层，对 Spring 几乎一样（Repository 多异常翻译）。

**@Qualifier / @Primary / @Value / @Profile / @Lazy / @Conditional / @PropertySource？**  
同类型多个用 Qualifier/Primary。Value 注值。Profile 环境。Lazy 延迟。Conditional 条件。PropertySource 引配置。

**单例 Bean 是否有并发安全问题？**  
有。单例有状态字段就会竞态。无状态 Service 才安全；状态放方法局部、ThreadLocal 或并发容器。

**IOC 容器初始化过程？Spring 的优点？**  
见 02。优点：生态、IoC/AOP、事务、测试、Boot 约定。

### 10 自调用失效

**Spring 事务在什么情况下会失效？**  
见 05。自调用：this.method() 不走代理，事务/@Async 都不生效。

**@Async 原理？什么时候失效？如何避免内部调用失效？**  
BPP 给 Bean 做代理，异步提交到线程池。失效：没开 `@EnableAsync`、自调用、返回值不是 void/Future。避免：注入自己、拆 Bean、AopContext.currentProxy()（要暴露代理）。

**事务传播行为有什么用？隔离级别？**  
见 05。

**@PostConstruct / @PreDestroy / @Scheduled / @Cacheable / @EventListener？**  
构造后/销毁前；定时（要 EnableScheduling）；缓存抽象；事件监听。都走容器，自调用同样可能失效。

### 11 过滤器与 MVC 注解

**拦截器和过滤器有什么区别？**  
Filter 是 Servlet，先于 DispatcherServlet，能改请求体。Interceptor 是 Spring MVC，能注入 Bean，围绕 Handler。顺序：Filter → DispatcherServlet → Interceptor → Controller。

**MVC 工作原理 / 核心组件 / 父子容器？**  
见 06。

**如何定义 Controller、处理表单、视图解析器、国际化、异常？**  
`@Controller`/`@RestController`；表单 `@ModelAttribute`/`@RequestParam`；ViewResolver 配前缀后缀；MessageSource 国际化；`@ControllerAdvice` + `@ExceptionHandler`。

**@RequestBody / @ResponseBody / @PathVariable / @RequestHeader / @CookieValue / @SessionAttribute / @ModelAttribute？**  
Body 反序列化 JSON；ResponseBody 序列化；路径变量；请求头；Cookie；Session；模型绑定/预填充。

**@Validated 和 @Valid？@ExceptionHandler / @ResponseStatus？**  
都能校验。Validated 是 Spring 的，支持分组。ExceptionHandler 处理异常；ResponseStatus 设 HTTP 状态。

**Restful 是什么？WebFlux 和 MVC 的差别？**  
REST：资源 + HTTP 动词 + 状态码。MVC Servlet 线程模型；WebFlux 响应式 Netty，适合高并发 IO，编程模型不同。

**Spring 和 Spring MVC 的关系？JPA 和 Hibernate？**  
见 06。JPA 是规范，Hibernate 是实现；Spring Data JPA 是仓库抽象。

## 05 其他

### 01 网络

**TCP/IP 四层、OSI 七层**  
TCP/IP：链路、网际（IP）、传输（TCP/UDP）、应用。OSI 多了会话、表示，面试能对应即可。

**TCP 连接 / 解决什么问题 / 与 UDP 区别**  
TCP 面向连接、可靠、有序、流、拥塞控制。UDP 无连接、尽全力、报文。视频/DNS 用 UDP，业务请求多用 TCP。

**三次握手、四次挥手、TIME_WAIT**  
握手：SYN → SYN+ACK → ACK，防历史连接、双方确认初始序号。挥手：FIN → ACK → FIN → ACK，半关闭。TIME_WAIT 等 2MSL，让 ACK 可靠、旧包消失。

**超时重传、滑动窗口、粘包拆包**  
超时/快速重传丢包。滑动窗口做流量控制。TCP 是流，没有消息边界 → 粘包。应用层定长/分隔符/长度字段。Netty 有解码器。

**HTTP vs HTTPS、1.0 vs 2.0、2.0 vs 3.0**  
HTTPS = HTTP + TLS。1.0 短连接；1.1 keepalive、管道。2 多路复用、头压缩、仍基于 TCP。3 基于 QUIC/UDP，减队头阻塞。

**Cookie Session Token**  
Cookie 浏览器存，可被带上。Session 服务器存会话，靠 Cookie 里 sessionId。Token（JWT）无状态，网关验签。XSS/CSRF 要一起防。

**从输入网址到页面显示**  
DNS → TCP（HTTPS 还 TLS）→ HTTP 请求 → 服务器 → 响应 → 浏览器解析 HTML/CSS/JS、可能再请求资源、渲染。

**什么是 BIO、NIO、AIO？Channel / Selector？**  
BIO 一连接一线程。NIO 多路复用，Selector 听 Channel 就绪。AIO 系统回调（Linux 上不比 epoll 香）。Java 网络主流 NIO/Netty。

**Java 的 I/O 流是什么？什么是网络编程？**  
字节流 InputStream/OutputStream，字符流 Reader/Writer。网络编程：Socket 上读写，现在多用 Netty/Web 框架。

### 02 MQ

**为什么需要 MQ、模型有哪些**  
解耦、削峰、异步。模型：队列点对点；Pub/Sub 广播。Rabbit 交换机；Kafka topic 分区；RocketMQ topic+tag。

**不丢失 / 幂等 / 有序 / 堆积 / 推拉**  
丢失：生产确认、持久化、消费 ACK。幂等：业务去重键。有序：单分区/单队列 + 单消费者。堆积：扩消费者、丢弃、降级。推拉：Kafka 拉；Rabbit 推为主。

**Rabbit 延迟队列、死信、无法路由**  
TTL + 死信交换机做延迟。死信：拒绝、过期、队列满。无法路由：mandatory + 备份交换机。

**RocketMQ NameServer、事务消息及缺点**  
NameServer 无状态路由。事务消息：半消息 + 本地事务 + 回查。缺点：回查压力、最终一致不是 XA。

**Kafka 与 ZK、事务消息**  
新版本 KRaft 去 ZK。事务：精确一次生产到分区，跨会话要幂等生产者 + 事务。

### 03 Netty

**几种 I/O 模型**  
阻塞、非阻塞、IO 多路复用、信号驱动、异步。Linux 网络主力 epoll 多路复用。

**Select Poll Epoll**  
select/poll 遍历 fd，有上限。epoll 事件回调 + 红黑树/链表，百万连接友好，ET/LT。

**Reactor 线程模型**  
主 Reactor 接连接，子 Reactor 读写，工作线程跑业务。Netty：boss + worker。

**Netty 场景 / 为何不用裸 NIO / 为何快**  
RPC、网关、IM。裸 NIO 空轮询、API 难。Netty：epoll、零拷贝、池化缓冲、pipeline。

**零拷贝、粘包拆包、空轮询、设计模式**  
sendfile/FileRegion 少拷贝。拆包 LengthFieldBasedFrameDecoder。JDK epoll 空轮询 Netty 重建 selector。模式：Reactor、责任链、观察者。

### 04 设计模式

**什么是设计模式**  
可复用的设计经验，不是具体代码。记常用几种和场景。

**最常见的几种及场景**  
单例（容器）、工厂（创建）、策略（if-else）、责任链（Filter）、模板（父类流程）、观察者（事件）、代理（AOP）。

**单例实现与线程安全**  
饿汉、双重检查（volatile）、静态内部类、枚举。Spring 单例是容器管，不是 JVM 里只有一个 Class。

**简单工厂**  
一个类里 if 创建，违背开闭，小规模可用。

**工厂 vs 抽象工厂**  
工厂方法：一种产品一族创建器。抽象工厂：一组相关产品。Spring FactoryBean 偏工厂方法。

**策略 / 责任链 / 模板 / 观察者 / 代理**  
策略：可替换算法。责任链：沿链传。模板：骨架固定、步骤可覆写。观察者：发事件。代理：加功能不改原类。

### 05 MyBatis

**MyBatis-Plus 是什么，和 MyBatis 的区别**  
MP 是增强：CRUD 生成、条件构造器、分页插件。底层还是 MyBatis。

**MyBatis vs Hibernate**  
MyBatis SQL 可控、半自动。Hibernate ORM 全自动、SQL 难控。国内业务多用 MyBatis。

**`#{}` 和 `${}`**  
`#{}` 预编译参数，防注入。`${}` 字符串拼接，表名动态才用，必须白名单。

**缓存机制**  
一级：SqlSession 内。二级：Mapper 级，默认关，集群下易脏，生产常关或谨慎。

**插件原理如何写插件**  
拦截 Executor/StatementHandler 等，实现 Interceptor，`@Intercepts` 签名。分页插件就是这么干。

### 06 场景与排查

**限流算法**  
固定窗口、滑动窗口、漏桶、令牌桶（Redis + Lua 常见）。网关层 + 服务层。

**秒杀 / 分布式 ID / 短链 / 点赞 / RPC 框架**  
秒杀：库存预减 Redis、令牌、异步下单、独立部署。ID：号段、Snowflake。短链：hash + 冲突、302。点赞：Redis 计数 + 异步落库。RPC：接口、序列化、发现、负载、超时重试。

**分布式锁一般怎么实现**  
见 Redis 06。ZK/etcd 会话型。

**线上 CPU 飙高如何排查**  
top 看进程 → `printf "%x" pid` → jstack 多次对照 nid 看热点栈。GC 狂也飙 CPU，先看 GC 日志。Arthas thread/profiler。

**进程线程区别、物理地址逻辑地址（操作系统）**  
进程资源单位，线程调度单位，同进程共享地址空间。CPU 跑虚拟/逻辑地址，MMU 映射物理页。
